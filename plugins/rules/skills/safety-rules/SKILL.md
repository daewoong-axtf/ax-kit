# safety-rules

「AI로 만든 웹앱 최소 안전 규칙」을 프로젝트에 넣는다. 이미 들어 있으면 최신 판으로 올린다. 명령은 하나이고, 처음 넣는지 올리는지는 프로젝트를 보고 정한다.

규칙의 내용은 이 스킬에 복사해 두지 않는다. 릴리즈된 원문을 받아 그대로 넣는다.

## 부르는 법

| 어디서 | 설치 | 부르기 |
| --- | --- | --- |
| Claude Code | `/plugin install rules@ax-kit` | `/rules:apply` |
| Codex(ChatGPT) 등 이 스킬만 설치한 곳 | `npx skills add daewoong-axtf/ax-kit --skill safety-rules` | `/safety-rules`, 또는 아래처럼 말로 시킨다 |

어디서든 "최소 안전 규칙 넣어줘", "안전 규칙 최신 판으로 올려줘"라고 말해도 된다.

## 위치

| 무엇 | 위치 |
| --- | --- |
| 버전 목록 | `https://daewoong-axtf.github.io/ax-kit/guides/index.json`의 `guides["safety-rules"]` — `latest`, `versions[].version` · `path` |
| 규칙 원문 | `https://daewoong-axtf.github.io/ax-kit/<path>` (예: `guides/safety-rules/1.3.0.md`) |
| 변경 기록 | `https://raw.githubusercontent.com/daewoong-axtf/ax-kit/main/rules/safety-rules/CHANGELOG.md` |
| 프로젝트의 규칙 파일 | 프로젝트 맨 위 폴더의 `daewoong-coding-guide.md` |
| 프로젝트의 진입 파일 | 프로젝트 맨 위 폴더의 `CLAUDE.md` · `AGENTS.md` |

프로젝트 맨 위 폴더는 `git rev-parse --show-toplevel`이 알려 주는 폴더다. git 저장소가 아니면 지금 폴더다. 프론트엔드와 백엔드가 한 저장소에 있어도 규칙 파일은 맨 위에 하나만 둔다.

규칙 파일의 판은 첫 줄 `# AI로 만든 웹앱 최소 안전 규칙 (vX.Y.Z)`에 적혀 있다. 첫 줄이 이 모양인 파일만 규칙 파일로 본다.

## 순서

1~4번은 읽고 정하기만 한다. 프로젝트의 파일은 5번부터 쓴다.

1. **넣을 판을 정한다.** `curl -fsSL`로 버전 목록을 받는다. 사용자가 판을 말했으면 `versions`에서 그 판을, 말하지 않았으면 `latest`와 같은 판을 찾아 그 `path`를 쓴다. 목록에 없는 판이면 있는 판을 알려 주고 멈춘다.

2. **프로젝트에 지금 있는 판을 읽는다.** 맨 위 폴더에서 아래를 차례로 본다.
   - `daewoong-coding-guide.md`가 있으면 그 첫 줄의 판이 지금 판이다.
   - 없는데 `CLAUDE.md`나 `AGENTS.md`의 첫 줄이 규칙 파일 모양이면 **옛 방식**이다. 규칙 원문의 이름을 바꿔 진입 파일로 쓴 것이다. 그 첫 줄의 판이 지금 판이다.
   - 둘 다 아니면 처음 넣는 것이다.

3. **같은 판이면 멈춘다.** 지금 판이 넣을 판과 같고 옛 방식이 아니며 진입 파일이 이미 규칙 파일을 가리키면(6번) "이미 <판>이다"라고 알리고 멈춘다. 아무것도 받지 않는다. 지금 판이 넣을 판보다 높으면 내리는 것이 맞는지 사용자에게 묻는다.

4. **원문을 임시 폴더로 받아 확인한다.** 임시 폴더는 하나만 만들고, 출력된 경로를 적어 둔다. 명령마다 셸이 새로 뜨면 변수는 사라지므로 뒤 단계에서는 적어 둔 경로를 그대로 쓴다.
   ```
   TMP=$(mktemp -d) && echo "$TMP" && curl -fsSL "https://daewoong-axtf.github.io/ax-kit/<path>" -o "$TMP/new.md" && head -1 "$TMP/new.md"
   ```
   첫 줄이 `# AI로 만든 웹앱 최소 안전 규칙 (v<넣을 판>)`이 아니면 넣지 않는다.

   옛 방식이면 지금 판의 원문도 같은 임시 폴더에 `old.md`로 받아 그 진입 파일과 `diff`한다. 다른 곳이 있으면 프로젝트에서 손댄 것이다. 원문에 없던 줄을 더한 것은 **덧붙인 내용**, 원문의 줄을 바꾸거나 지운 것은 **규칙을 고친 것**으로 나눈다. 지금 판의 원문을 받지 못했으면 진입 파일 전체를 프로젝트에서 고친 것으로 본다.

5. **규칙 파일을 쓴다.** 받은 원문을 맨 위 폴더의 `daewoong-coding-guide.md`로 그대로 복사한다. 이미 있으면 바꾼다. 내용은 한 글자도 고치지 않는다. 이미 있던 파일이 그 판의 원문과 달랐어도(누군가 고쳤어도) 새 원문으로 바꾸고, 바뀌었던 곳이 있었다고 보고에 적는다.

6. **진입 파일이 규칙 파일을 가리키게 한다.** 아래 블록을 진입 파일에 넣는다.

   ```markdown
   ## 최소 안전 규칙

   작업을 시작하기 전에 `daewoong-coding-guide.md`를 처음부터 끝까지 읽고 항상 따른다. 이 규칙 파일은 고치지 않는다.

   @daewoong-coding-guide.md
   ```

   - 어느 파일에 넣는가: `CLAUDE.md`와 `AGENTS.md` 중 프로젝트에 있는 것 모두. 한쪽이 다른 쪽을 불러오면(`@AGENTS.md` 줄이 있거나 심볼릭 링크) 불러오는 대상에만 넣는다. 불러오는 쪽에 다른 내용이 더 있어도 같다. 둘 다 없으면 `CLAUDE.md`를 만들어 넣는다. Claude Code가 아닌 도구에서 이 스킬을 따르고 있으면 `AGENTS.md`를 만든다.
   - 어디에 넣는가: 파일 첫 줄이 `# `로 시작하는 제목이면 그 바로 아래, 아니면 맨 위. 블록 앞뒤는 빈 줄 하나로 띄운다. 이미 있는 내용은 지우거나 옮기지 않는다.
   - 진입 파일에 `daewoong-coding-guide.md`를 가리키는 줄이 이미 있으면 넣지 않는다.
   - **옛 방식이면** 진입 파일 안의 규칙 원문을 위 블록으로 바꾼다. 규칙은 5번에서 `daewoong-coding-guide.md`로 옮겨졌다. 4번에서 덧붙인 내용이 나왔으면 바꾸기 전에 그 내용을 사용자에게 보여 주고 한 번 묻는다 — 블록 아래에 남길지, 버릴지. 답을 받기 전에는 진입 파일을 쓰지 않는다. 규칙을 고친 것은 남기지 않는다. 어느 줄이 어떻게 달랐는지 보고에 적는다.

7. **임시 폴더를 지운다.** 4번에서 적어 둔 경로 하나만 `rm -rf "<그 경로>"`로 지운다. 중간에 멈출 때도 지운다. `tmp.*` 같은 와일드카드로 지우지 않는다. 임시 폴더에는 다른 프로그램의 파일도 있다.

8. **보고한다.**
   - 처음 넣었는지 올렸는지, 판(`1.2.0 → 1.3.0`)과 기준일
   - 만들거나 바꾼 파일
   - 올렸으면 그사이 바뀐 것: 변경 기록을 받아 지금 판 다음부터 넣은 판까지의 항목을 쉬운 말로 요약한다. 받지 못하면 `https://github.com/daewoong-axtf/ax-kit/releases`를 알려 준다
   - 새 규칙은 **새 대화부터** 읽힌다. 이 대화에서 작업을 이어 가려면 `daewoong-coding-guide.md`를 지금 읽고 따른다
   - 커밋하지 않았다는 것. 커밋할 파일 목록을 알려 준다

## 멈출 때

- 버전 목록이나 원문을 받지 못하면 규칙을 기억으로 쓰지 않는다. 받지 못한 이유를 알리고 멈춘다. 프로젝트의 파일은 그대로 둔다.
- 맨 위 폴더에 규칙 파일 모양이 아닌 `daewoong-coding-guide.md`가 있으면 덮어쓰지 않는다. 무슨 파일인지 사용자에게 묻는다.

## 하지 않는 것

- 사용자가 요청하지 않았는데 규칙을 넣거나 올리지 않는다.
- 규칙 원문을 고치거나, 줄이거나, 일부만 넣지 않는다.
- 진입 파일에 있던 프로젝트 고유 내용을 묻지 않고 지우지 않는다.
- 새 규칙에 맞춰 코드를 고치지 않는다. 규칙 파일을 넣는 데서 끝낸다. 고칠 곳이 보이면 보고에 적는다.
- 사용자가 요청하지 않으면 커밋하거나 푸시하지 않는다.
