# 메일·웍스 문의 대응 기록

사용자가 메일·메신저(네이버웍스) 대화 원문이나 요약을 주면, 노션 **AX 라운지 메일·메신저 문의** DB에 페이지를 하나 만들고 속성과 본문을 채운다.

## 대상 DB

- DB: https://app.notion.com/p/9f2f14132e65431e8bf51c3e3aa94f4a
- 데이터 소스: `collection://1feac73a-930e-4afa-a669-866c4c883441`
- 만들기 전에 이 데이터 소스를 한 번 fetch해서 속성 이름과 선택지가 아래와 같은지 확인한다. 다르면 fetch 결과를 따른다.

| 속성 | 타입 | 채우는 법 |
| --- | --- | --- |
| 문의 (제목) | title | `[부서] 문의 내용 요약` — 예: `[SCM-위수탁팀] 발주산출 AI 운영 방향 문의 (Claude API 비용 vs 로컬 Ollama)` |
| 접수일 | date | 첫 문의가 온 날짜 (`date:접수일:start`, `is_datetime` 0) |
| 부서 | text | 부서명만. 개인 이름은 넣지 않는다 |
| 채널 | multi_select | 방문 / 메일 / 메신저 / 미팅 중 해당하는 것. 웍스 메신저는 `메신저` |
| 유형 | select | AX 과제 발굴·구현 / 사내 로그인 연동(SSO) / 조직/인사정보 연계 / 사내 API/AI 활용 / 사내 시스템/데이터 연계 / 기술 검토·문제 해결 / 서버 배포·운영 / 기타 중 하나 |
| 상태 | status | 접수 / 답변 대기 / 보류 / 답변 완료. AX팀 답변이 나갔으면 `답변 완료`, 현업 회신·결정을 기다리면 `답변 대기` |
| TF 담당 | person | 대응한 AXTF 인원. Notion 사용자 검색(query_type "user")으로 찾고, 모르면 비운다 |

| 관련 과제 | relation | 사용자가 과제를 알려준 경우에만 |
| FAQ 반영 | checkbox | 건드리지 않는다 |

## 본문 형식

아래 다섯 섹션을 이 순서로 쓴다. 제목은 속성에만 넣고 본문에 다시 쓰지 않는다. **`대응 이력`은 항상 본문 맨 마지막 섹션**이며, 시간순 이력이 하나뿐이어도 빼지 않는다.

```
## 현업의 문제(과업)
- 현업이 하려는 일, 결정해야 하는 것

## 현업이 겪은 어려움
- 실제로 막힌 점, 비용·속도·정확도 등 구체적인 숫자와 사실

## AX팀의 지원 내용
### 1. <무엇을>
- 어떤 방법으로: 구체적인 방법, 설정값, 도구, 담당
### 2. <무엇을>
- ...
(표가 필요한 비교 정보는 Notion 표로)

## 결과
- 실제로 일어난 일(발급, 적용, 해결, 비용 등)과 날짜
- 남은 일이나 제안 중인 사항은 "제안" 또는 "진행 중"이라고 분명히 표시

## 대응 이력
- YYYY.MM.DD HH:MM 이름: 한 줄 요약
```

- `대응 이력`은 시간순 원문 요약이다. 날짜·시각과 말한 사람이 있으면 남긴다(시각을 모르면 날짜만). 원문 문장을 통째로 붙이지 않는다.
- AX팀이 보낸 회신(메일·메신저)도 `대응 이력`에 `YYYY.MM.DD 보낸 사람 → 받는 사람 메일 회신: 한두 문장 요약` 형태로 남긴다.
- 1차·2차 문의처럼 이어지는 페이지 링크는 본문 맨 위 인용 줄(`> 1차 문의: <mention>`)에 둔다. `대응 이력` 아래에는 다른 섹션을 두지 않는다.
- AX팀 답변에 번호(1, 2, 2-1, 3…)가 있으면 지원 내용 소제목에 그 번호를 살린다. 후속 대화가 "2·3·5번"처럼 번호로 가리키기 때문이다.

## 작성 원칙

- 받은 내용에 있는 사실만 쓴다. 결과가 대화에 없으면 지어내지 말고 결과에 "확인 필요"라고 쓴 뒤 사용자에게 묻는다.
- 내가 계산하거나 추정한 숫자(예: 6일 사용액을 월로 환산)는 `참고:`로 시작하는 별도 줄에 두고 원문 숫자와 섞지 않는다.
- 부서명, 유형, 상태처럼 대화로 확정되지 않는 값은 가장 그럴듯한 것으로 채우고, 끝에 무엇을 추정했는지 짧게 알린다.
- 간결한 개조식 한국어로 쓴다.

## 진행 순서

1. 받은 컨텍스트에서 부서, 접수일, 채널, 문의자·대응자, 문제, 어려움, AX팀 지원(번호별), 결과, 시간순 이력을 뽑는다.
2. 데이터 소스를 fetch해 스키마를 확인한다.
3. 같은 건이 이미 있는지 `문의`·`부서`로 검색한다. 있으면 새로 만들지 말고 사용자에게 업데이트할지 묻는다.
4. TF 담당자가 있으면 사용자 검색으로 user ID를 찾는다.
5. `notion-create-pages`로 parent `data_source_id: 1feac73a-930e-4afa-a669-866c4c883441`에 속성과 본문을 함께 만든다.
6. 사용자에게 링크와 함께 채운 속성 요약, 추정한 값, 확인이 필요한 점만 짧게 알린다.

## 기존 페이지에 추가 대응을 넣을 때

- 먼저 페이지를 fetch한다. 사용자가 직접 고친 문구는 바꾸지 않는다.
- 새 대응은 `대응 이력` 맨 끝에 시간순으로 한 줄씩 더하고, `결과`에 새 사실을 추가한다. `insert_content`나 좁은 `update_content`만 쓰고 `replace_content`는 쓰지 않는다.
- 기존 페이지에 `대응 이력` 섹션이 없으면 본문 맨 밑에 `## 대응 이력` 섹션을 만들어 이력을 넣는다.
- 상태와 `답변·안내`, `근거`(새 날짜 추가)도 함께 갱신한다.
